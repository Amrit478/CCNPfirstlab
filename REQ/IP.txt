Yes. Now we move to the **IP addressing design phase**. This should happen **before configuring VLANs, EIGRP, OSPF, BGP, GRE, or VRFs**.

The correct engineering process is:

> **Customer requirements → Count hosts/networks → Choose private address blocks → Subnet using VLSM → Assign gateways → Assign point-to-point addresses → Configure routing**

I will give you a complete addressing plan for the lab based on the topology and customer scenario we created.

# Step 2 — Choose a Large Private Address Block

We first need an overall address range.

Let's assign:

```text
10.0.0.0/8
```

But we should organize it properly.

For example:

```text
10.10.0.0/16  = HQ Campus
10.20.0.0/16  = Branch
10.100.0.0/16 = Infrastructure / WAN
10.200.0.0/16 = ISP / External Lab
```

Instead of randomly doing:

```text

192.168.200.0
```

we organize the company logically.

# PHASE 1 — HQ LAN Addressing

## VLAN 10 — HQ Users

The customer needs up to **100 users**.

We ask:

> What subnet supports at least 100 usable hosts?

### Calculate the subnet

We know:

```text
2^6 - 2 = 62 hosts
```

Not enough.

Try 7 host bits:

```text
2^7 - 2 = 126 usable hosts
```

That works.

Therefore:

```text
32 - 7 = /25
```

So VLAN 10 gets:

```text
Network:       10.10.10.0/25
Subnet Mask:   255.255.255.128
Usable Range:  10.10.10.1 - 10.10.10.126
Broadcast:     10.10.10.127
Gateway:       10.10.10.1
```

### Why `.1` as the gateway?

We need an IP address assigned to the Layer 3 SVI.

For example:

```text
VLAN 10 Network
10.10.10.0/25

Gateway
10.10.10.1
     |
     |
HQ-DSW1 / HQ-DSW2
     |
     |
PCs
10.10.10.10
10.10.10.11
10.10.10.12
```

There is nothing magical about `.1`.

You could use:

```text
10.10.10.126
```

as the gateway.

But using `.1` consistently is easier to manage.

# Step 3 — How Do We Handle Two Distribution Switches?

Your topology has:

```text
HQ-DSW1
HQ-DSW2
```

We do **not** give both switches the same ordinary SVI IP address.

Because you want redundancy, we use an FHRP such as **HSRP**.

For VLAN 10:

```text
Virtual Gateway:  10.10.10.1
HQ-DSW1:          10.10.10.2
HQ-DSW2:          10.10.10.3
```

The PCs use:

```text
Default Gateway = 10.10.10.1
```

Conceptually:

```text
                HSRP Virtual IP
                  10.10.10.1
                       |
              -------------------
              |                 |
        HQ-DSW1             HQ-DSW2
       10.10.10.2          10.10.10.3
```

If DSW1 fails, DSW2 can take over the virtual gateway.

This is much more realistic than making every PC use DSW1 directly.

---

# HSRP Addressing Pattern

We can consistently use:

```text
Gateway Virtual IP = .1
DSW1 = .2
DSW2 = .3
```

For example:

| VLAN | HSRP Gateway | DSW1       | DSW2       |
| ---- | ------------ | ---------- | ---------- |
| 10   | 10.10.10.1   | 10.10.10.2 | 10.10.10.3 |
| 20   | 10.10.20.1   | 10.10.20.2 | 10.10.20.3 |
| 30   | 10.10.30.1   | 10.10.30.2 | 10.10.30.3 |
| 40   | 10.10.40.1   | 10.10.40.2 | 10.10.40.3 |
| 99   | 10.10.99.1   | 10.10.99.2 | 10.10.99.3 |

This gives you a very clean addressing convention.

# PHASE 5 — FVRF Addressing

This is important.

Your **physical WAN interfaces** can belong to the FVRF.

For example:

```text
VRF Name: WAN-FVRF
```

HQ Router:

```text
Physical WAN Interface
IP: 10.200.0.1/30
VRF: WAN-FVRF
```

Branch Router:

```text
Physical WAN Interface
IP: 10.200.0.6/30
VRF: WAN-FVRF
```

The ISP addresses are reachable through the underlay.

Conceptually:

```text
             WAN-FVRF
HQ Router ---------------- ISP ---------------- Branch Router

10.200.0.1                                  10.200.0.6
```

The important concept is:

> **The FVRF is used so the routers know how to reach the GRE tunnel destination through the underlay.**

# PHASE 6 — GRE Tunnel Addressing

The GRE tunnel itself needs its own IP network.

We do **not** use the physical WAN IP addresses as the tunnel interface IPs.

Let's assign:

```text
10.255.0.0/30
```

This is the logical tunnel network.

```text
Network:       10.255.0.0/30
Mask:          255.255.255.252
```

Assign:

```text
HQ Tunnel0:      10.255.0.1/30
Branch Tunnel0:  10.255.0.2/30
```

Conceptually:

```text
                     UNDERLAY
          10.200.x.x through ISP / FVRF

HQ-Router -------------------------------- Branch-Router
     \                                        /
      \______________________________________/
                    GRE Tunnel

                 OVERLAY NETWORK
                    10.255.0.0/30

HQ Tunnel0: 10.255.0.1
Branch T0:  10.255.0.2
```

Now you can run:

```text
OSPF Area 0
```

across:

```text
Tunnel0
```

# How I Actually Found These IP Addresses

This is the most important part for you to understand.

I did **not randomly choose them**.

I followed this process every time:

### Example: Customer needs 100 users

```text
Need ≥ 100 usable addresses

2^6 - 2 = 62    ❌
2^7 - 2 = 126   ✅
```

Therefore:

```text
7 host bits

32 - 7 = /25
```

So:

```text
100 users → /25
```

---

### Example: Customer needs 50 servers

```text
2^5 - 2 = 30    ❌
2^6 - 2 = 62    ✅
```

Therefore:

```text
50 hosts → /26
```

---

### Example: Customer needs 20 devices

```text
2^4 - 2 = 14    ❌
2^5 - 2 = 30    ✅
```

Therefore:

```text
20 hosts → /27
```

---

### Example: Router-to-router link

Only two interfaces need addresses:

```text
2^2 - 2 = 2
```

Therefore:

```text
2 hosts → /30
```

So you get:

```text
10.100.0.0 = Network
10.100.0.1 = Router A
10.100.0.2 = Router B
10.100.0.3 = Broadcast
```

That is exactly how you derive the subnet.

# Your Addressing Decision Process

Whenever you design a new network, ask these questions in this exact order:

### Question 1

**What is this network for?**

Example:

```text
Users
Servers
Management
Voice
WAN
Router transit
Tunnel
```

### Question 2

**How many hosts does the customer need?**

Example:

```text
100 users
50 servers
20 management devices
2 routers
```

### Question 3

**What is the smallest subnet that supports that number?**

```text
100 → /25
50  → /26
30  → /27
20  → /27
2   → /30
```

### Question 4

**Which large address block belongs to that site?**

```text
HQ      → 10.10.0.0/16
Branch  → 10.20.0.0/16
Transit → 10.100.0.0/16
WAN     → 10.200.0.0/16
```

### Question 5

**What will be the default gateway?**

For user VLANs:

```text
Usually HSRP/VRRP virtual IP
Example: x.x.x.1
```

For point-to-point links:

```text
There is no "default gateway" configured on the interface in the same sense.
The routing table determines where traffic goes.
```

### Question 6

**Document everything before configuring devices.**

Only after this IP plan is complete should you begin Phase 1 configuration.
