# Your other point: "Why don't companies use routers everywhere?"

Correct. **Most enterprise networks do not need a router between every switch or VLAN.**

A modern multilayer switch can do this:

```text
VLAN 10 ──┐
          │
VLAN 20 ──┼── IOL/Catalyst L3 Switch ── Routing
          │
VLAN 30 ──┘
```

The L3 switch can provide:

* Default gateways using SVIs
* Inter-VLAN routing
* OSPF
* EIGRP
* Static routes
* HSRP/VRRP
* ACLs

And it does so at high speed inside the LAN.

Therefore, a typical small/medium enterprise might look like:

```text
Internet
   |
ISP Modem/ONT
   |
Firewall
   |
L3 Switch
   |
-------------------------
|           |           |
Access      Access     Servers
Switch      Switch
Switch
```

In this design, the **firewall is usually the security boundary**, while the L3 switch handles internal routing.

# The important correction: BGP is not only for ISPs

This part needs a small correction.

You said:

> "We do not do a lot of routing unless you are an ISP."

Not exactly.

**Almost every medium or large enterprise does routing internally.** For example:

```text
Users VLAN
     |
Servers VLAN
     |
Voice VLAN
     |
Guest VLAN
     |
Data Center
     |
Branch Office
```

Traffic between these Layer 3 networks requires routing.

But that routing may happen on:

* Multilayer switches
* Firewalls
* Routers
* SD-WAN devices

So the better statement is:

> **Most enterprises do plenty of routing, but they do not necessarily need dedicated routers everywhere.**

And:

> **BGP is not only used by ISPs. Enterprises may use BGP for ISP connectivity, multiple providers, data centers, cloud connectivity, MPLS, or large-scale routing designs.**

For example:

```text
                   Enterprise
                       |
              +--------+--------+
              |                 |
             ISP 1             ISP 2
            AS 100            AS 200
              |                 |
            eBGP              eBGP
              \                 /
               Enterprise Edge
```

An enterprise may use BGP even though it is **not an ISP**.

# The biggest concept you just discovered

You are now understanding **network roles**, rather than thinking:

> "I need to put routers here because routers do routing."

Instead, the engineering question is:

> **What function does this part of the network need?**

For example:

### Access layer

Needs lots of Layer 2 ports:

```text
→ L2 Switch
```

### Distribution layer

Needs switching **and** routing:

```text
→ L3 Switch
```

### WAN edge

Needs advanced WAN and routing functions:

```text
→ Router / CSR1000v
```

### Internet boundary

Needs security inspection:

```text
→ Firewall
```

That is much closer to how you should think when designing enterprise networks.
